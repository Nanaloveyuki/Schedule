## 当前技术折中

原计划存储层是 Room，但实际构建阶段踩到 `AGP 9.x + built-in Kotlin + KSP` 组合兼容问题。

因此当前仓库采用的折中方案是：

- 保留 `ScheduleRepository` 抽象
- 暂时使用 `SharedPreferences + JSON + StateFlow` 做本地存储

这不是最终方案，但它适合当前阶段：

- 先把产品和交互做出来
- 避免被构建链路卡死
- 保留以后切回 Room 的空间

## 后续最值得做的事情

### 第一优先级

- 把课程编辑和提醒任务页从“手输 ID”改成选择器
- 优化课表查看页排序和展示
- 增加空状态与录入引导

### 第二优先级

- 实现真正的应用内通知
- 实现普通提醒调度
- 补真机提醒测试

### 第三优先级

- 在权限允许时写入系统日历事件
- 增加事件删除和同步策略

## 当前不建议优先做的事情

- 立即恢复 Room + KSP
- 引入大规模依赖升级
- 为跨端而重构 Android 主线架构
- 在首版阶段优先做 Rust/Tauri 共享层实验

## 当前稳定工作方式

每次改动安卓端时，优先遵守以下顺序：

1. 先读 `apps/android` 当前配置。
2. 先跑 `./gradlew assembleDebug`。
3. 先修构建问题，再写业务。
4. 写完后再次编译。
5. 再做模拟器或真机验证。
